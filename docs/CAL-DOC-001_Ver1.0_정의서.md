# 1. 프로젝트 한 줄 정의

컴퓨터를 켜는 순간부터 자연스럽게 함께하는, **로컬 우선(local-first) Windows 데스크톱 캘린더**.
월간 캘린더를 중심으로 일정 / To-Do / 메모를 한 화면에서 관리하고, LLM으로 입력과 정리를 줄여 준다.
핵심 사용 방식은 **바탕화면 위젯**이다. 다른 창 뒤(바탕화면 위)에 항상 떠 있다가 필요할 때 바로 보고 쓴다 (위젯 모드, FR-DESK-005).

# 2. 확정된 결정

| 항목 | 결정 |
| --- | --- |
| UI | Python + PySide6 (Qt) |
| 데이터 | SQLite, `%APPDATA%\FlowCalendar\flowcalendar.db` |
| 서버 / 계정 | **없음.** 로그인, 회원가입, 프로필, Firebase, FastAPI, PostgreSQL 사용하지 않음 |
| LLM | **BYOK** (사용자가 자기 API 키 입력). 기본 제공자 Gemini, 제공자는 어댑터로 교체 가능 |
| 키 저장 | Windows 자격 증명 관리자 (`keyring`). 파일/DB에 평문 저장 금지 |
| 배포 | PyInstaller + Inno Setup 설치 파일 |
| 대상 | Windows 10, 11 |

서버를 두지 않는 이유: Ver1.0은 한 대의 PC에서 쓰는 개인용 앱이라 서버가 필요한 요구(다중 기기, 공유, 계정)가 없다.
데이터 접근은 `repository` 계층에 모아서, 나중에 동기화 서버를 붙일 수 있게 한다.

# 3. Ver1.0 범위

## 포함

| 영역 | 내용 |
| --- | --- |
| 캘린더 | 월간 뷰, 오늘 강조, 월 이동, 날짜 Hover 시 "+" 버튼 |
| 일정 | 생성·수정·삭제, 파스텔 5색, 라운드 박스, 단순 반복(매일·매주·매월) |
| Daily To-Do | 날짜별 To-Do, 체크박스, 우선순위 |
| Quick To-Do | 날짜와 연결되지 않는 To-Do (우측 패널) |
| Quick Memo | 날짜와 연결되지 않는 메모 카드 (우측 패널) |
| 데스크톱 연동 | **위젯 모드(바탕화면 뒤 고정, 반투명 배경)**, 트레이 상주, Windows 시작 시 자동 실행, 일정 시작 전 토스트 알림 |
| LLM | 자연어 빠른 추가, 오늘/이번 주 브리핑 |
| 설정 / 데이터 | 알림, 자동 시작, API 키, JSON 내보내기·가져오기 |
| 배포 | 설치 파일 |

## 제외 (Ver1.x 이후)

- Week / Day 뷰 (다크 모드는 **검정 테마로 구현됨**, FR-SET-003)
- 루틴, 프로젝트 관리, 통계, Daily Memo
- 협업, 외부 캘린더 연동, Android / iOS / Web
- 로그인, 회원가입, 프로필, 회원탈퇴

# 4. 요구사항 ID 규칙

- 기능: `FR-코드-번호` / 비기능: `NFR-번호`

## AI LLM 기능

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-AI-001 | 자연어 빠른 추가: "내일 오후 3시 팀 미팅 1시간" 같은 입력을 일정 또는 To-Do로 변환한다. 기본은 **확인 없이 바로 등록**하고 등록 직후 5초 동안 **되돌리기**를 제공한다. 설정에서 끄면 미리보기(채워진 입력 팝업)로 보여 주고 사용자가 확인해야 저장한다. 같은 날 같은 제목이 이미 있으면 등록을 건너뛴다. | High |
| FR-AI-002 | 오늘 브리핑: 오늘(또는 이번 주)의 일정과 To-Do를 요약하고, 시간이 겹치는 일정을 알려 준다. 앱 시작 시 1회 표시하며 끌 수 있다. | Medium |
| FR-AI-003 | 설정에서 제공자(Gemini 기본 / Claude / OpenAI)와 API 키를 입력한다. 키가 없으면 AI 기능 UI를 숨긴다. | High |
| FR-AI-004 | 한도 초과, 네트워크 오류, 응답 파싱 실패 시 오류 안내 후 수동 입력으로 전환한다. | High |
| FR-AI-005 | LLM 은 데이터를 직접 쓰지 못한다 (저장은 항상 앱이 한다). 메모에서 만든 후보는 항상 사용자가 체크해 확인한 것만 등록한다. ✨ 빠른 추가는 사용자가 직접 입력한 문장이므로 기본으로 확인 없이 등록하되(FR-AI-001), 되돌리기를 제공하고 설정에서 확인 방식으로 바꿀 수 있다. | High |
| FR-AI-006 | **메모에서 일정/할 일 만들기**: 메모에서 사용자가 **선택한 줄만** AI로 보내 일정·Daily To-Do·Quick To-Do **후보**로 바꾼다. 후보 목록에서 체크한 것만 등록하고(이미 같은 제목이 같은 날에 있으면 기본 해제), 각 후보를 수정할 수 있다. 메모 내용은 바꾸지 않는다. 자동(백그라운드) 변환은 하지 않는다. | Medium |
| FR-AI-007 | **처리하지 못한 입력 목록**: ✨ 빠른 추가가 실패하거나(키·모델·서버·시간 초과 등) 일정/할 일을 찾지 못하면 입력한 글을 잃지 않게 목록에 남긴다. 목록은 빠른 추가 팝업 아래에 보이고 3줄까지만 보이며 나머지는 스크롤한다. 줄마다 다시 시도 / 직접 입력 / 삭제를 제공하고, 같은 글은 한 줄만 두며, 다시 시도해 성공하면 지운다 (최대 50개). | Medium |
| FR-AI-008 | **모델 자동 대체**: 쓰던 모델이 없어졌다는 오류(404)가 나면, 내 키로 쓸 수 있는 모델 목록에서 이름이 가장 비슷한 것으로 한 번만 다시 시도하고, 성공하면 그 모델을 설정에 저장한 뒤 알려 준다. 그 사이 사용자가 모델을 직접 바꿨으면 건드리지 않는다. | Medium |
| FR-AI-009 | 시작 브리핑은 AI 응답을 **10초**만 기다리고 자동 재시도하지 않는다. 늦거나 실패하면 코드로 계산한 요약을 바로 보여 준다. | Medium |

**AI 데이터 전송 원칙**
- 전송: 대상 기간의 일정·남은 To-Do **제목과 시간**, 사용자 입력 문장, 오늘 날짜·요일·시각, 그리고 사용자가 메모에서 직접 선택해 변환을 요청한 글(FR-AI-006)
- 비전송: 선택하지 않은 메모 본문, 완료한 To-Do, 키 값 자체 외의 모든 설정
- 무료 티어는 입력 데이터가 제품 개선에 쓰일 수 있으므로 설정 화면에 안내 문구를 둔다 (Google 약관 확인 필요).

# 8. 데이터 모델 (초안)

```sql
schedules(
  id INTEGER PK, title TEXT NOT NULL,
  start_at TEXT NOT NULL,       -- ISO 8601 로컬 시각
  end_at TEXT, all_day INTEGER DEFAULT 0,
  color TEXT NOT NULL,          -- yellow|pink|green|blue|purple
  recurrence TEXT,              -- NULL | daily | weekly | monthly
  recurrence_until TEXT,
  remind_before_min INTEGER,    -- NULL이면 알림 없음
  created_at TEXT, updated_at TEXT
)

recurrence_exceptions(          -- 반복 일정의 "이 일정만" 수정/삭제
  id INTEGER PK, schedule_id INTEGER REFERENCES schedules(id),
  occurrence_date TEXT NOT NULL, is_deleted INTEGER DEFAULT 0,
  override_title TEXT, override_start_at TEXT, override_end_at TEXT
)

todos(
  id INTEGER PK, title TEXT NOT NULL,
  date TEXT,                    -- NULL이면 Quick To-Do, 값이 있으면 Daily To-Do
  done INTEGER DEFAULT 0, priority INTEGER DEFAULT 1,
  done_at TEXT,                 -- 완료한 시각 (보관 기간 계산용, 스키마 v3)
  sort_order INTEGER, created_at TEXT, updated_at TEXT
)

memos(id INTEGER PK, content TEXT, created_at TEXT, updated_at TEXT)   -- Ver1.0은 1행만 사용, 여러 카드 확장 대비 테이블로 유지

ai_inbox(id INTEGER PK, text TEXT NOT NULL, reason TEXT, created_at TEXT)   -- AI 가 처리하지 못한 빠른 추가 입력 (FR-AI-007)

settings(key TEXT PK, value TEXT)    -- API 키는 저장하지 않음
schema_version(version INTEGER)
```

반복 일정은 한 행만 저장하고, 화면에 표시할 때 해당 월 범위로 전개한다.

# 9. 구조

```
src/flowcalendar/
├── app.py            # 앱 진입, 트레이, 단일 인스턴스
├── ui/               # PySide6 화면, 위젯, 팝업, 디자인 토큰
├── domain/           # 모델, 반복 전개, 검증 (UI와 DB를 모른다)
├── data/             # SQLite 연결, 마이그레이션, repository
├── services/         # 알림 스케줄러, 자동 시작, 백업
└── ai/               # LLM 어댑터 (gemini / claude / openai), 프롬프트, 응답 스키마
```

규칙: `ui → domain / services → data` 방향으로만 의존한다. `ui`가 SQLite를 직접 열지 않는다.

# 11. 기존 문서 대비 변경 이유

| 변경 | 이유 |
| --- | --- |
| Flutter + FastAPI + PostgreSQL + Firebase → PySide6 + SQLite | 처음 계획(노션 메인 페이지)의 스택과 일치. 서버·계정 운영 부담 제거 |
| 사용자(USER) 요구사항, 로그인 계열 화면 삭제 | 로컬 단일 사용자 앱 |
| 루틴 / 프로젝트 / Week·Day 뷰 → Ver1.x 이후 (다크 모드는 테마 기능에 포함해 v1.0.0에서 구현) | 001과 003이 서로 달랐던 범위를 003 기준으로 통일 |
| 트레이, 자동 시작, 알림 추가 | 비전("컴퓨터를 켜는 순간부터 함께")의 핵심 |
| LLM 기능 추가 | 사용자 요청. BYOK로 서버 없이 구현 |
| NFR 추가 | 기존 003에 비어 있었음 |
| Daily To-Do 삭제에 Undo 추가 | "확인 없이 즉시 삭제"의 실수 방지 |
| 위젯 모드(FR-DESK-005, 006) 추가 | 기획 목표가 "바탕화면 위젯처럼 다른 창 뒤에 항상 떠 있는 캘린더"임을 확인 (초안에는 빠져 있었다) |
| 문서 번호 재정리 | 기존 003이 가리킨 004~007이 실제 문서와 달랐음 |

# 12. 결정 기록

| 질문 | 결정 |
| --- | --- |
| 반복 종료 조건 | 무기한 + 종료일. 횟수 지정은 Ver1.1 |
| 여러 날 일정 | 새 열 없이 `end_at`의 날짜로 표현 (스키마 변경 없음). 종일은 종료일 00:00, 시간 일정은 종료일 + 종료 시각. 다음 날 00:00에 끝나는 시간 일정은 전날까지로 본다 |
| 일정 끌어서 이동·복제 | 칩/막대 끌기=이동, Ctrl=복사, 복제 버튼=내용이 채워진 새 일정 팝업. 반복 일정은 그 회차만. 5초 되돌리기 |
| 자동 백업 | 하루 1회, 최근 7개, 기본 켬. 업그레이드 직전 백업은 별도 이름으로 보관(지우지 않음) |
| 완료한 할 일 | 기본 30일 보관 후 자동 삭제(7/30/90일/계속 선택). 정리 직전에 자동 백업을 먼저 한다 |
| AI 모델 대체 | 404 시 비슷한 모델로 1회 재시도, 성공하면 설정에 저장하고 안내. 브리핑은 10초·재시도 없음 |
| 검색 | 일정·할 일 제목 + 메모 내용, 종류별 최대 30건, 반복 일정은 한 건 |
| 배포 방식 | PyInstaller 실행 폴더(one-folder, 콘솔 창 없음, 안 쓰는 Qt 부품 제외) + Inno Setup 설치 파일(`FlowCalendar-Setup-1.0.0.exe`, 관리자 권한 없이 내 계정에 설치) |
| 설치 중 선택 | 바탕화면 바로가기, Windows 시작 시 자동 실행(트레이로 시작)은 기본 꺼짐으로 설치 때 고른다. 설정 화면의 자동 실행과 같은 항목을 쓴다 |
| 제거 | 프로그램 파일과 시작 메뉴·자동 실행 항목만 지운다. **내 데이터(`%APPDATA%\FlowCalendar`)는 지우지 않는다** |
| 코드 서명 | 하지 않음. Windows SmartScreen 경고가 뜰 수 있어 README에 안내 (개인·지인 배포 기준) |
| 성능 | 켜기 2초, 월 이동 100ms를 `tools/measure_perf.py`로 측정(방법·결과는 CAL-PERF-001). 접힌 일정은 위젯을 만들지 않는 방식으로 월 이동 394ms → 64ms |
| AI 빠른 추가 진입점 | 헤더 ✨ 버튼 + 팝업, 전역 단축키로도 열림 |
| Quick Memo | 시안대로 한 장의 불릿 메모 |
| 개발 환경 | Python 3.13 + 프로젝트 내 가상환경(`.venv`), PySide6-Essentials |
| 테마 | **Rose Glass(분홍)가 기본**이고, 설정에서 11가지(분홍·보라·노랑·하늘·연두·회색·흰색·검정(다크)·그라데이션 노을/라벤더/민트)를 고를 수 있다. 고르면 바로 적용되고(저장 전에는 미리보기, 닫으면 저장된 테마로 복귀), 저장하면 다음 실행에도 유지된다(`settings.theme`, 스키마 변경 없음). 색은 `ui/tokens.py`의 테마 표에서 정하며, 앱 아이콘은 테마와 무관하게 고정. 일정 색 5가지는 모든 테마에서 같은 색 계열이고 검정에서만 어둡게 눌러 쓴다. 실제 배경 블러(Windows Acrylic)는 쓰지 않음 |
| 메모 → 일정/할 일 AI 변환 | 선택한 줄만 전송, 후보 목록에서 확인한 것만 등록, 메모는 바꾸지 않음(표시 안 함). 메모 전체를 보내거나 자동 등록하는 방식은 전송 원칙·FR-AI-005 때문에 채택하지 않음 |
| 빠른 추가의 확인 | 사용자 결정(2026-10-28): 빠른 추가가 목적이므로 확인 없이 바로 등록한다. 대신 5초 되돌리기, 중복 건너뛰기, 설정에서 끄기를 둔다. 메모 변환은 여러 개를 고르는 방식이라 확인 목록을 유지한다 |
| 처리하지 못한 입력 | 잃지 않게 목록에 남겨 팝업 아래에 3줄까지 보이고 스크롤한다. 메모 변환의 실패는 메모가 그대로 남아 있으므로 목록에 넣지 않는다 |
| AI 통신/모델 | Python 기본 `urllib` 로 직접 호출(새 패키지 없음). 모델 이름은 설정에서 제공사별로 바꿀 수 있고 비우면 기본값 |
| 브리핑 표시 | 앱 시작 시 화면 오른쪽 아래 작은 카드(몇 초 뒤 자동 닫힘, 오늘/이번 주 전환). 시간 겹침은 코드가 계산하고 AI는 요약 문장만 만든다 |
| 위젯 모드 클릭 동작 | 클릭·입력해도 앞으로 올라오지 않고 계속 뒤에 둔다 (사용자가 직접 부를 때만 잠깐 앞으로) |
| 위젯 배경 투명도 | 위젯 모드에서만 배경을 반투명(기본 65%, 설정 슬라이더 50~100%). 블러 없이 투명도만 쓴다. 일반 창은 Windows 제약(테두리 있는 창은 투명 불가)과 가독성 때문에 불투명 유지. 팝업도 불투명 유지. 헤더 보조 띠는 넣지 않음 |
